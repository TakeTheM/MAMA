# 5. MVP 가설, 기능 목록, 가정·위험, 클라이언트 질문지, 미팅 준비

> 목표: 우리가 만들 것과 모르는 것을 목록으로 만들고, 모르는 것을 클라이언트가 답할 수 있는 질문으로 바꾼다.

> **작성 메모**: [클라이언트 미팅 1](client-meeting-1.md)(2026-10-19)의 답변과 [AI 확인 기록](../domain/ai-check-log.md#질문지-검토-5단계)의 질문지 검토(2026-10-20)를 반영한 판입니다. 미팅 1에서 `[사실]`로 확인된 것은 "(Q1)"처럼 답변 번호를 붙였고, 나머지는 다음 미팅 전까지 `[가정]`입니다. 기능 ID(F-01~F-08)와 '고객사 설정 1~3'은 client-meeting-1.md에서 쓴 번호를 그대로 따릅니다.

## 5-1. MVP 가설

> 클라이언트 미팅 전 우리의 추측입니다. 미팅 뒤 바뀔 수 있습니다. 제안서 Ⅰ-3 제안 범위, Ⅳ-10 목표 흐름의 바탕이 됩니다.

| 구분 | 내용 |
| --- | --- |
| 핵심 사용자 흐름 1개 (첫 데모에서 보여 줄 것) | 셀러 대표가 **광고 한 건**(마케팅 캠페인)을 만들어 승인하고, 직접 올린 뒤 결과를 확인하는 흐름. 기획중 → 초안 생성됨 → 검수 대기 → 수정 요청 → 검수 대기 → 승인됨 → 게시 예약됨 → 집행중 → 종료 → 성과 평가 완료 (03 3-2). 클라이언트가 "광고를 올리고 예산을 쓰는 일은 사용자가 한다"고 답했으므로(Q3), 게시 예약됨 → 집행중 → 종료는 외부 플랫폼 연동이 아니라 **사장님이 '게시함'·'종료'를 직접 기록**하는 것으로 둡니다 `[가정]` (H1). 데모 예시는 클라이언트의 지난 광고(10만원·7일)를 그대로 다시 만들어 봅니다 `[사실]` (Q1) |
| 이 흐름에서 LLM이 쓰이는 곳 | ① 기획중 → 초안 생성됨: 상품·목표·채널을 받아 캡션·해시태그 초안을 쓴다 (L1, F-01) ② 검수 대기 → 승인됨 / 수정 요청: 과장·효능 표방·협찬 미표시·비하 표현을 찾아 이유, 근거 자료, 고쳐 쓴 문장을 제안한다 (L2, F-02). 상태는 금지어 규칙과 사장님 승인이 바꾼다 ③ 종료 → 성과 평가 완료: 시스템이 계산한 성과 숫자를 쉬운 말로 요약하고 다음 광고 제안을 쓴다 (L3, F-05). 이 요약은 다음 광고의 초안(①)에 참고 자료로 들어간다(피드백 루프, Q1 새 요구) |
| 당장 제외할 것과 이유 | ① 사진·이미지 제작: 클라이언트가 캡션 작성·수정(7시간 중 4시간)을 가장 큰 부담으로 꼽았고 F-01을 캡션·해시태그로 한정함 (Q1) ② 서비스가 대신 게시·광고 집행·예산 관리: 서비스는 글 작성과 검증만 맡기를 원함 (Q3, 피드백 4). 그래서 R7(예산 초과 방지)과 자동 일시정지도 뺌 ③ 광고 문자·DM 발송: 서비스가 보내지 않으므로 R2와 3-3 야간 발송 규칙은 MVP 범위 밖 ④ 광고 효과·매출 **예측 숫자**와 AI 페르소나 소비자 반응 예측: 결과를 확인할 방법이 캠페인이 끝나야 생김 (03 3-4) ⑤ 인플루언서 섭외·계약·정산: 범위가 크고 인플루언서 정보가 개인정보임 (4-4 후보 B, 02 2-3). 협찬 표시 검수만 선택 기능(F-08)으로 둠 ⑥ 원가 절감 재료 비교: 필수 조건 미통과 (4-2 후보 C) |

## 5-2. 주요 기능 목록

> 5~8개. '필수'는 첫 데모에 꼭 있어야 하는 기능, '선택'은 시간이 되면 만드는 기능입니다. 제안서 Ⅳ-11의 바탕이 됩니다.

| ID | 기능명 | 설명 | 사용자 | 우선순위 (필수/선택) | 관련 상태 전이 / LLM |
| --- | --- | --- | --- | --- | --- |
| F-01 | 캡션·해시태그 초안 | 상품 정보·광고 목표·채널을 입력하면 채널 형식에 맞춘 캡션과 해시태그 초안을 만든다. 지난 광고의 문구와 성과(F-05 결과)가 있으면 참고한다(피드백 루프). 사진은 만들지 않는다 (Q1) | 셀러 대표 | 필수 | 기획중 → 초안 생성됨 / LLM ○ (L1) |
| F-02 | 광고 문구 검수와 대체 표현 제안 | 검수를 요청한 문구에서 거짓·과장(R3), 식품·화장품 효능 표방(R4), 협찬 미표시(R1), 비하·혐오(R5) 위험 표현을 찾아 이유, 근거 자료(법령·심사지침·기사 원문 링크), 고쳐 쓴 문장을 보여 준다. 금지어 규칙 목록으로 한 번 더 거른다 (피드백 3) | 셀러 대표 | 필수 | 검수 대기 → 승인됨 / 수정 요청 / LLM ○ (L2) |
| F-03 | 승인과 캠페인 상태 관리 | 사장님이 승인해야 '승인됨'이 되고, 승인 전에는 게시 단계로 넘어가지 않는다(R6). 수정 후 다시 검수 요청, 집행 전 취소를 할 수 있다. 캠페인마다 상태와 바뀐 기록을 보여 준다 | 셀러 대표 | 필수 | 초안 생성됨 → 검수 대기, 수정 요청 → 검수 대기, 검수 대기 → 승인됨, 기획중·초안 생성됨·게시 예약됨 → 취소 / LLM × |
| F-04 | 게시·집행 기록 | 사장님이 플랫폼에 직접 올린 뒤 '게시함'·'종료'·'플랫폼 반려'를 기록한다. 게시 예정 시각이 심사 24시간 여유보다 가까우면 알려 준다(3-3). 플랫폼 자동 게시·집행 연동은 H1이 틀릴 때만 넣는다 | 셀러 대표 | 필수 (수동 기록) / 자동 연동은 선택 | 승인됨 → 게시 예약됨 → 집행중 → 종료, 게시 예약됨 → 플랫폼 반려 → 수정 요청 / LLM × |
| F-05 | 성과·수익 확인 보고서 | 종료 뒤 노출·클릭·전환·광고비·매출을 입력(연동은 H8 확인 뒤)하면 시스템이 ROAS와 수익을 계산하고, LLM이 쉬운 말로 요약해 다음 광고 제안을 쓴다. 숫자는 LLM이 아니라 시스템이 계산한다 (03 3-4 L3) | 셀러 대표 | 필수 (Q1 새 요구) | 종료 → 성과 평가 완료 / LLM ○ (L3) |
| F-06 | 리뷰 요약 | 상품 리뷰에서 자주 나온 장점·불만을 요약해 다음 광고 기획에 참고하게 한다. 리뷰 작성자 이름·아이디는 LLM에 보내지 않는다 | 셀러 대표 | 선택 | 기획중 (참고 자료) / LLM ○ (L3) |
| F-07 | 원가 반영 수익 계산 | 원가·플랫폼 수수료·배송비를 입력하면 F-05 수익을 실제 이익 기준으로 계산한다 (01 1-2 '마진'). H3에서 '수익'이 매출·ROAS로 확인되면 뺀다 | 셀러 대표 | 선택 | 종료 → 성과 평가 완료 / LLM × |
| F-08 | 협찬 게시물 표시 검수 | 인플루언서가 만든 협찬 게시물 초안에 광고 표시가 첫 부분·첫 번째 해시태그에 있는지, '체험단'·'AD' 같은 부적절한 문구를 썼는지 F-02 규칙으로 검사한다 (R1, 2-ketarubot-01) | 셀러 대표 | 선택 | 검수 대기 → 승인됨 / 수정 요청 / LLM ○ (L2) |

> 제안 요약의 '핵심 기능 3가지'는 F-01, F-02, F-03입니다. F-04는 상태를 끝까지 지나가기 위한 기록 기능이고, F-05는 미팅 1에서 새로 생긴 필수 요구입니다.

## 5-4. 위험 요소

> 2~3개. 예: LLM이 틀린 답을 낸다, 개인정보가 LLM에 들어간다, 기능이 늘어나 8주 안에 못 끝낸다. 제안서 Ⅶ-17의 바탕이 됩니다.

| 위험 | 일어나면 생기는 일 | 대응 |
| --- | --- | --- |
| LLM 검수(F-02)가 위험 표현을 놓치거나, 너무 많이 잡거나, 없는 근거 자료를 지어낸다 | 놓치면 사장님이 서비스를 믿고 올린 광고가 제재·논란으로 이어진다. 너무 많이 잡으면 사장님이 경고를 무시한다. 지어낸 기사·조항을 보여 주면 서비스 신뢰가 무너진다 (ai-check-log에도 AI가 근거 없는 내용을 답한 사례가 여러 건 있음) | ① LLM 결과를 금지어 규칙 목록으로 한 번 더 거른다 (03 3-4 L2) ② R1·R3·R4 위반 예문 테스트 세트(4-4 ①)로 스프린트마다 놓친 비율과 잘못 잡은 비율을 잰다 ③ 근거 자료는 팀이 미리 모아 확인한 자료(법령·심사지침 원문, 확인한 기사)에서만 인용하고, 링크가 없는 근거는 보여 주지 않는다 ④ 화면에 '최종 판단은 사용자'를 밝히고 상태는 사장님 승인으로만 바뀐다 (R6) |
| 개인정보·영업 비밀이 LLM에 들어간다 | 개인화 AI(H9)나 리뷰 요약(F-06)에 고객 이름·연락처, 리뷰 작성자 정보, 매입 단가가 섞여 외부 LLM으로 나간다 | ① 03 3-4의 'LLM에 보내지 않을 정보' 목록을 입력 단계에서 걸러 내고(마스킹), 테스트로 확인한다 ② 개인화 입력은 H9 확인 전까지 과거 광고 문구와 성과 숫자로만 한정한다 ③ 원가는 시스템 계산(F-07)에만 쓰고 LLM에는 보내지 않는다 |
| 기능이 늘어나 8주 안에 핵심 흐름을 끝내지 못한다 | 미팅 1에서 수익 확인, 개인화 AI, 피드백 루프, 근거 자료 제시가 새로 생겼고, 선택 기능(F-06~F-08)과 플랫폼 연동(H1·H8)까지 넣으면 3주차에 핵심 흐름 1개를 돌리지 못한다. 기능마다 LLM을 부르면 비용도 커진다 (피드백 2) | ① 3주차 데모는 F-01~F-03과 수동 기록(F-04·F-05)만으로 처음부터 끝까지 지나가게 한다 ② 플랫폼 연동은 H1·H2·H8 확인 뒤 S3 이후에 정한다 ③ 선택 기능은 클라이언트가 정한 우선순위(질문 6, 고객사 설정 3) 순서로 S4부터 넣는다 ④ 새 요구는 결정 기록장에 적고 그만큼 다른 기능을 빼는지 함께 정한다 |

## 5-5. 클라이언트 질문지

> 카테고리마다 1개 이상, 총 8~10개. 미팅 질문 시간은 팀당 약 12분이므로 우선순위 1~5번은 반드시 묻는 질문입니다. **1~3번은 제안서 Ⅶ-18에 넣어 미리 보냅니다.** 질문을 고칠 때 팀원끼리 서로 읽어 보고 예/아니오로 끝나거나 답을 유도하는 질문을 고칩니다.
>
> 좋은 질문의 조건: ① 예/아니오로 끝나지 않는다 ② 구체적인 사례를 들어 묻는다 ③ 우리 해결책을 정답으로 유도하지 않는다 ④ 답을 들으면 무엇을 결정할지 알고 있다.
