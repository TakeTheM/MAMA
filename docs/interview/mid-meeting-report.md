## 보고서 당시 현황과 현재 코드

보고서의 개발 상태는 작성 당시 기록이다. 아래 현재 코드는 2026-11-17 브랜치의 파일을 대조한 결과이며 실제 배포·AI·DB 통합 검증 완료를 뜻하지 않는다.

| 항목 | 보고서 당시 | 현재 코드에서 확인한 것 | 남은 확인 |

## 중간 미팅 시연 시나리오

보고서에서 제안한 시연은 목업 데이터 기준이며 실제 광고 게시·광고비 집행·실측 성과 시연이 아니다. 현재 앱의 기본 모드는 실제 API이므로 같은 시연을 하려면 DB·LLM 설정 또는 별도 목업 구성이 필요하다.

1. 수제 그래놀라의 상품명·특징·가격·목표·채널·예산을 입력한다.
2. 채널별 캡션·해시태그를 확인하고 직접 수정한다.
3. 위험 표현·이유·근거·대체 문구를 확인한다. 필요하면 수정 후 재검수하고, 경고를 확인한 뒤 사용자가 승인한다.
4. 일정·예산을 저장하고 플랫폼에 직접 올렸다는 가정으로 게시·종료를 기록한다.
5. 예시 성과를 입력해 ROAS와 요약을 확인하고 평가를 완료한다. 다음 기획에서 지난 캠페인 참고를 확인한다.

별도 경로는 게시 예약된 광고의 플랫폼 반려 사유 기록 → 다시 고치기 → 수정·재검수 → 승인·재예약이다. 게시 전 취소는 현재 허용 상태(기획중·초안 생성됨·게시 예약됨)에서 확인한다.

## 클라이언트에게 확인할 것

- 실제 광고 업무에서 도움이 되는 단계와 불필요한 단계는 무엇인가?
- 위험 표현과 대체 문구를 판단할 때 어떤 근거가 필요한가? 경고 확인 후 직접 승인하는 방식에 우려가 있는가?
- 남은 기간에 가장 먼저 개선할 기능은 무엇인가?
- 위험 탐지와 자연스러운 대체 문구 중 어느 쪽을 보강해야 하는가?
- ‘수익’은 매출·ROAS인가, 원가·수수료를 뺀 실제 이익인가?
- 실제 사용 채널·업종과 신뢰할 수 있는 근거 자료 범위는 무엇인가?

위 질문은 확인 요청이며 고객 답변이 기록된 것은 아니다. 기사 자동 수집·RAG, 플랫폼 자동 게시·성과 수집, 실제 이익 계산·이미지 생성은 이번 MVP에 넣지 않는다.

## 보고서의 후속 계획과 현재 남은 일

1. 보고서는 로그인·회원가입과 계정별 저장을 첫 우선순위로 제시했다. 현재는 공유 작업공간이므로 인증 재도입의 범위와 우선순위를 팀이 다시 결정한다.
2. 보고서는 PR #43 마무리와 목업의 실제 API 연결을 제안했다. 현재 연결 코드는 있으므로 배포 환경에서 광고 한 건의 생성부터 평가 완료·다음 초안 참고까지 저장·상태·이력을 검증한다.
3. 실제 AI로 초안·검수·성과 요약을 검증한다. 수정 후 재검수, 허용하지 않은 근거 링크, 호출 실패·재시도, 플랫폼 반려·취소 경로를 확인한다.
