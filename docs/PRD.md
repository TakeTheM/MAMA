## 1. 개요

MAMA는 SNS 광고를 직접 만들고 게시하는 소상공인·이커머스 셀러를 위한 광고 문구 작성·검수 및 캠페인 관리 도구다. 상품 정보로 채널별 초안을 만들고 위험 표현의 이유와 대체 문구를 보여 준다. 사용자가 승인한 광고의 게시·종료 기록과 성과를 한곳에서 관리한다.

개발 기간은 8주, 팀 합계 20시간이다. 현재 구현은 로그인 없는 공유 작업공간이며, 보고서가 제안한 계정별 관리는 후속 결정 사항이다.

## 2. 사용자 여정

상품·목표·채널·예산 입력 → 채널별 초안 → 위험 표현 확인·필요시 수정·재검수 → 사용자 승인 → 게시 일정 → 직접 게시·종료 기록 → 성과 입력·요약 확인·평가 완료

정상·반려·취소 경로와 시연 범위는 [사용자 흐름](requirements/user-flows.md)을 따른다.

## 3. 기술 스택

Next.js·TypeScript 화면 → `/api/*` rewrites → FastAPI → PostgreSQL/Supabase. LLM 호출·상태 전이·ROAS 계산·DB 접근은 백엔드가 맡는다. 테스트는 Vitest·Pytest이며 현재 백엔드 배포 절차는 Vercel 기준이다.

현재 구성과 초기 Render 계획의 차이는 [기술 스택](STACK.md), 설치·실행은 [루트 README](../README.md)와 [백엔드 README](../backend/README.md)를 따른다.

기능·스토리 번호와 인수 조건의 기준은 [백로그](requirements/backlog.md)다. 이 문서에는 조건을 중복해서 적지 않는다.

## 5. 데이터·상태·사용자 결정

상태 이름과 전이는 [도메인 문서 3-2](domain/03-rules-states-llm.md#3-2-핵심-대상과-상태-전이), 현재 API 계약은 [백엔드 README](../backend/README.md)와 [OpenAPI](../backend/docs/openapi.json)를 따른다.

- 위험 표현은 경고다. 검수가 완료된 현재 문구는 경고가 있어도 사용자가 승인할 수 있다. LLM 결과만으로 승인하거나 수정 요청 상태로 바꾸지 않는다.
- 게시·종료·플랫폼 반려는 사용자의 수동 기록이다. 서비스가 외부 플랫폼에 게시하거나 상태를 자동 전환하지 않는다.
- ROAS는 서버가 계산한다. 요약 생성 뒤에도 사용자가 평가 완료를 눌러야 상태가 바뀐다.
- 현재는 모든 호출자가 같은 작업공간을 사용한다. 계정별 소유권 검사는 구현돼 있지 않다.

LLM 입력과 보내지 않을 정보는 [도메인 문서 3-4](domain/03-rules-states-llm.md#3-4-llm이-들어갈-자리)를 따른다.
