## 현재 접근 범위와 후속 요구

현재 구현은 로그인 없는 공유 작업공간이다. 모든 호출자가 같은 캠페인을 조회하고 허용된 동작을 실행한다. 아래 인수 조건의 사용자도 이 범위를 따른다. 보고서가 제안한 로그인·계정별 저장·소유권 검사는 후속 요구이며 현재 완료 조건에 포함된 것으로 간주하지 않는다. 도입할 때는 모든 스토리의 접근 검사와 US-01·US-05의 참고 광고 범위를 함께 변경한다.

## US-01 캡션·해시태그 초안 받기

**셀러 대표로서, 상품·목표·채널·예산을 입력하면 캡션·해시태그 초안을 받고 싶다. 캡션을 처음부터 쓰는 시간을 줄이기 위해서다.**

- 우선순위: 필수
- 관련 기능: F-01
- 경로: 정상
- 관련 상태 전이: 기획중 → 초안 생성됨
- LLM 관여: 예
- 관련 이슈: (다음 주에 채움)

### 인수 조건

- (정상) 기획중 캠페인에 상품명·상품 특징·가격·광고 목표·채널(1개 이상)·예산(금액, 기간)을 모두 입력하고 '초안 만들기'를 누르면, 고른 채널마다 캡션 1개와 해시태그 목록 1개가 만들어지고 상태가 기획중 → 초안 생성됨으로 바뀐다. 상태 기록이 1줄 남는다.
- (정상, 피드백 루프) 공유 작업공간에 성과 평가 완료 캠페인이 있으면, 가장 최근에 평가를 완료한 캠페인의 캡션·해시태그와 성과 숫자·요약(US-05)을 LLM 입력에 함께 넣고, 초안 화면에 참고한 캠페인을 표시한다. 없으면 참고 없이 만들고 아무것도 표시하지 않는다.
- (실패) 필수 입력이 하나라도 비어 있거나 예산 금액·기간이 0 이하이면 LLM을 부르지 않고 빈 항목을 표시한다. 상태는 기획중 그대로다.
- (실패) LLM 호출이 실패하거나, 응답에 고른 채널 중 하나라도 캡션이 없으면 오류를 보여 주고 상태는 기획중 그대로다. 입력한 내용은 지워지지 않는다.
- (접근 범위) 공유 작업공간의 사용자가 초안을 생성할 수 있다. 서버는 현재 상태와 입력을 검사한다.
- (LLM 경계) 초안 생성됨이 되어도 검수 요청은 자동으로 되지 않는다. 다음 상태로는 사장님이 US-02에서 직접 요청해야만 간다.
- (LLM에 보내지 않을 정보) LLM 요청 본문에는 고객 이름·연락처·주소와 매입 단가(원가)가 들어가지 않는다. 피드백 루프 입력도 지난 광고의 문구·성과 숫자·요약으로 한정한다 (H9).

### 미확정

- 지원 채널이 인스타그램·X·틱톡이 맞는지, 채널별 캡션 글자 수·해시태그 개수 제한 (H2)
- 현재는 최근 평가 완료 캠페인 1건을 참고한다. 계정별 저장 도입 시 참고 범위, 성과 기준·참고 건수 확장 여부 (H3, H9)
- 초안 다시 만들기 횟수 제한 (LLM 비용, 미팅 1 피드백 2)
- 초안 생성됨 → 기획중 되돌림('다시 기획')을 후속 범위로 허용할지

## US-02 초안 검수 요청하기

**셀러 대표로서, 초안을 고친 뒤 검수를 요청하고 싶다. 광고를 올리기 전에 확인받기 위해서다.**

- 우선순위: 필수
- 관련 기능: F-03
- 경로: 정상
- 관련 상태 전이: 초안 생성됨 → 검수 대기
- LLM 관여: 아니오
- 관련 이슈: (다음 주에 채움)

### 인수 조건

- (정상) 초안 생성됨 캠페인에서 사장님이 캡션·해시태그를 고치고 '검수 요청'을 누르면 고친 내용이 저장되고 상태가 초안 생성됨 → 검수 대기로 바뀐다. 상태 기록이 1줄 남는다.
- (정상) 검수 대기가 되면 그 시점에 저장된 문구로 US-03의 검수가 시작된다. 고치지 않고 바로 요청해도 같다.
- (실패) 고른 채널 중 캡션이 비어 있는 채널이 하나라도 있으면 검수 요청을 거절하고 상태는 초안 생성됨 그대로다.
- (실패) 승인됨·취소 등 검수가 허용되지 않는 상태에서는 요청을 거절한다. 수정 요청·검수 대기에서의 재검수는 US-03을 따른다. 기존 문자열 전용 캠페인은 기획중에서 `content`로 검수를 요청할 수 있는 호환 경로가 있다.
- (접근 범위) 공유 작업공간의 사용자가 문구를 고치고 검수를 요청할 수 있다. 검수 처리 중에는 문구 변경을 거절한다.

### 현재 동작과 미확정

- 검수 처리 중에는 문구 변경을 거절한다. 경고가 있는 검수 완료 또는 실패 상태에서는 새 문구를 제출해 다시 검수할 수 있다. 검수 실패·연결 중단 뒤에는 본문 없는 재시도도 허용한다 (현재 API 기준).
- 계정별 저장을 도입할 때 초안 작성자와 검수 요청자·승인자를 구분할지 (H6)

## US-03 위험 표현 확인하고 수정하기

**셀러 대표로서, 초안의 위험 표현과 이유·근거·대체 문구를 보고, 수정 여부와 최종 승인을 직접 결정하고 싶다. 광고를 올리기 전에 판단할 정보를 얻기 위해서다.**

- 우선순위: 필수
- 관련 기능: F-02, F-03
- 경로: 정상·재검수 (플랫폼 반려 후 수정은 US-07에서 진입)
- 관련 상태 전이: 검수 대기 유지·재검수 → 사용자 승인 → 승인됨. 플랫폼 반려 후에는 수정 요청 → 검수 대기 → 승인됨.
- LLM 관여: 예 (판단 자료 제공)

### 인수 조건

- (경고) 검수 결과에 R1·R3·R4·R5 위험 표현이 있으면 표현별 위치·규칙 번호·이유·근거 링크(허용 자료가 있을 때)·대체 문구를 보여 준다. 상태는 검수 대기를 유지한다. 위험 표현만으로 수정 요청 상태로 바꾸거나 승인을 막지 않는다.
- (규칙 보조) LLM이 위험 표현을 놓쳐도 서버의 고정 표현 규칙에 해당하면 경고를 추가한다. 이 경고도 자동 상태 전이·승인 차단을 하지 않는다.
- (수정·재검수) 경고를 확인한 사용자가 문구를 수정해 재검수를 요청할 수 있다. 검수 대기에서 재검수하면 상태를 유지하고 현재 문구의 검수 결과를 갱신한다. 플랫폼 반려 후 수정 요청에서 검수하면 검수 대기로 전환한다.
- (승인) 현재 문구의 검수가 완료(`review.status=passed`)되면 경고가 있어도 승인 버튼이 켜진다. 사용자가 눌러야 승인됨으로 전환하고 상태 기록이 남는다. `passed`는 위험 표현 없음이 아니라 검수 완료를 뜻한다.
- (거절) 검수 실패·처리 중이거나 수정 요청 상태인 경우 승인을 거절한다. 먼저 현재 문구의 검수를 완료해야 한다.
- (실패) LLM 호출·응답 검증이 실패하면 오류를 보여 주고 상태는 검수 대기를 유지한다. 본문 없이 재시도할 수 있으며 검수 완료 전에는 승인할 수 없다.
- (근거 자료) 서버의 허용 목록에 없는 링크는 표시하지 않는다. 기사 자동 수집·RAG는 구현 범위 밖이며 자료·업종 확장은 고객 확인 뒤 정한다.
- (LLM 경계) 대체 문구는 사용자가 적용·수정해야 반영된다. LLM이 문구를 자동 확정하거나 승인하지 않는다.
- (접근 범위) 공유 작업공간 사용자가 수정·재검수·승인할 수 있다. 검수 처리 중에는 문구 변경을 거절한다.
- (LLM 입력) 광고 문구와 상품 카테고리만 보낸다. 고객 정보·원가·비밀값은 보내지 않는다.

### 미확정

- 업종별 검수 범위와 신뢰할 근거 자료, 대체 문구 품질의 우선순위 (H7·H10·H12)
- 현재 승인 후 문구 변경은 금지다. 승인 취소·재승인을 별도 경로로 허용할지 (H13)
- 계정별 저장 도입 시 작성자·검수 요청자·승인자의 권한을 나눌지

## US-04 게시 시각·예산 정하기

**셀러 대표로서, 승인된 광고의 게시 예정 시각과 예산을 정하고 싶다. 심사 시간 여유가 부족하면 미리 알림을 받기 위해서다.**

- 우선순위: 필수
- 관련 기능: F-04
- 경로: 정상
- 관련 상태 전이: 승인됨 → 게시 예약됨
- LLM 관여: 아니오
- 관련 이슈: (다음 주에 채움)

### 인수 조건

- (정상) 승인됨 캠페인에서 게시 예정 시각과 예산(금액, 기간)을 입력하고 저장하면 상태가 승인됨 → 게시 예약됨으로 바뀐다. 예산 칸에는 US-01에서 입력한 예산이 기본값으로 들어가 있다.
- (알림) 게시 예정 시각이 저장 시각부터 24시간 안이면 "플랫폼 심사에 24시간 여유가 없습니다" 알림을 보여 준다. 저장은 막지 않는다 (3-3).
- (실패) 게시 예정 시각이 저장 시각보다 과거이거나, 예산 금액·기간이 0 이하이면 거절하고 상태는 승인됨 그대로다.
- (실패) 승인됨이 아닌 상태에서 저장하면 거절하고 상태는 바뀌지 않는다.
- (접근 범위) 공유 작업공간의 사용자가 허용 상태에서 게시 시각과 예산을 정할 수 있다.
- (범위) 게시 예약됨이 되어도 서비스는 외부 플랫폼에 게시하거나 광고비를 집행하지 않는다. 외부 플랫폼 API를 부르지 않는다 (R6, H1).

### 미확정

- 채널마다 게시 예정 시각을 따로 정하는지
- 게시 예약을 취소하면 승인됨으로 돌아가는지 (03 3-2 '예약 취소'), 캠페인 취소(US-06)와 어떻게 다른지
- TikTok·X 심사 시간과 주말 심사 지연 (S1 자료 조사)

## US-05 성과 요약과 다음 광고 제안 받기

**셀러 대표로서, 광고가 끝난 뒤 성과 숫자를 입력하면 쉬운 말로 된 결과 요약과 다음 광고 제안을 받고 싶다. 이 광고로 수익이 났는지 확인하고 다음 광고에 반영하기 위해서다.**

- 우선순위: 필수
- 관련 기능: F-05
- 경로: 정상
- 관련 상태 전이: 종료 → 성과 평가 완료
- LLM 관여: 예
- 관련 이슈: (다음 주에 채움)

### 인수 조건

- (정상) 종료 캠페인에 노출·클릭·전환·광고비·매출을 입력하면 시스템이 ROAS(매출 ÷ 광고비)를 계산하고, LLM이 그 숫자로 결과 요약과 다음 광고 제안을 쓴다. 상태는 아직 종료 그대로다.
- (LLM 경계) 사장님이 요약을 확인하고 '평가 완료'를 누르면 상태가 종료 → 성과 평가 완료로 바뀐다. 누르기 전에는 바뀌지 않는다.
- (숫자는 시스템이) 화면의 숫자(입력값, ROAS)는 시스템이 계산한 값을 그대로 보여 준다. LLM 출력에 있는 숫자로 바꾸지 않는다.
- (실패) 입력 칸이 하나라도 비어 있거나 음수이면 거절하고 LLM을 부르지 않는다. 광고비가 0이면 ROAS는 '계산할 수 없음'으로 표시한다.
- (실패) LLM 호출이 실패해도 입력한 숫자와 ROAS는 저장하고 보여 준다. 요약이 없으면 '평가 완료'를 누를 수 없고 상태는 종료 그대로다.
- (실패) 종료가 아닌 상태에서 성과를 입력하면 거절한다.
- (피드백 루프) 성과 평가 완료가 된 캠페인의 문구·숫자·요약은 공유 작업공간의 다음 캠페인 초안(US-01) 입력으로 쓰인다.
- (접근 범위) 공유 작업공간의 사용자가 성과를 입력하고 평가를 완료할 수 있다. 상태와 요약 준비 여부는 서버가 검사한다.
- (LLM에 보내지 않을 정보) LLM에는 성과 숫자와 광고 문구만 보낸다. 리뷰 작성자 이름·아이디, 주문 번호, 원가는 보내지 않는다.

### 현재 동작과 미확정

- '수익'이 실제 이익(수수료·광고비·배송비·원가를 뺀 값)인지 매출·ROAS인지 (H3, F-07)
- 현재는 종료 후 사용자가 성과를 입력한다. 플랫폼 전환 집계 기간에 따른 입력 제한은 적용하지 않는다.
- MVP는 수동 입력으로 정리했다. 플랫폼 자동 수집은 후속 범위다 (H8).
- 현재 평가 완료 뒤에는 숫자를 고칠 수 없다. 되돌림 허용 여부는 후속 결정이다.

## US-06 광고 취소하기

**셀러 대표로서, 광고를 올리기 전에 마음이 바뀌면 캠페인을 취소하고 싶다. 필요 없는 광고에 시간과 비용을 쓰지 않기 위해서다.**

- 우선순위: 필수
- 관련 기능: F-03
- 경로: 취소·반려
- 관련 상태 전이: 게시 예약됨 → 취소 (기획중·초안 생성됨 → 취소 포함)
- LLM 관여: 아니오
- 관련 이슈: (다음 주에 채움)

### 인수 조건

- (정상) 기획중·초안 생성됨·게시 예약됨 캠페인에서 사장님이 '캠페인 취소'를 누르면 상태가 취소로 바뀐다. 상태 기록에 이전 상태가 남는다.
- (거절) 집행중·종료·성과 평가 완료 캠페인의 취소 요청은 거절하고 상태는 바뀌지 않는다. "이미 올린 광고는 플랫폼에서 직접 중지해 주세요"를 보여 준다.
- (되돌릴 수 없음) 취소 상태에서는 문구 수정, 검수 요청, 게시 기록 등 상태를 바꾸는 요청을 모두 거절한다.
- (LLM 경계) 취소 전에 보낸 LLM 요청(초안 생성 등)의 결과가 취소 뒤에 도착해도 상태와 문구를 바꾸지 않는다.
- (접근 범위) 공유 작업공간의 사용자가 허용된 상태의 캠페인을 취소할 수 있다.

### 미확정

- 현재 취소는 기획중·초안 생성됨·게시 예약됨에서만 가능하다. 검수 대기·수정 요청·승인됨으로 허용 범위를 넓힐지는 후속 결정이다.
- 취소한 캠페인을 목록에서 숨길지, 지울 수 있는지
- 취소 사유를 입력받을지

## US-07 게시·종료 기록하기

**셀러 대표로서, 플랫폼에 직접 광고를 올린 뒤 '게시함'과 '종료'를 기록하고 싶다. 광고 한 건의 진행과 결과를 한곳에 남기기 위해서다.**

- 우선순위: 필수
- 관련 기능: F-04
- 경로: 정상, 취소·반려 (플랫폼 반려)
- 관련 상태 전이: 게시 예약됨 → 집행중 → 종료, 게시 예약됨 → 플랫폼 반려 → 수정 요청
- LLM 관여: 아니오
- 관련 이슈: (다음 주에 채움)

### 인수 조건

- (정상) 게시 예약됨 캠페인에서 '게시함'을 누르면 상태가 집행중으로 바뀌고 게시 시각이 기록된다.
- (정상) 집행중 캠페인에서 '종료'를 누르면 상태가 종료로 바뀌고 종료 시각이 기록된다.
- (반려) 게시 예약됨 캠페인에서 '플랫폼 반려'를 고르고 반려 사유를 입력하면 상태가 플랫폼 반려로 바뀐다. 사장님이 '다시 고치기'를 누르면 수정 요청으로 바뀌고, 수정 화면에 반려 사유가 함께 보인다.
- (실패) 반려 사유가 비어 있으면 거절하고 상태는 게시 예약됨 그대로다.
- (실패) 순서를 건너뛰는 요청(게시 예약됨에서 바로 종료, 승인됨에서 게시함 등)은 거절하고 상태는 바뀌지 않는다.
- (실패) 종료 시각이 게시 시각보다 앞서면 거절한다.
- (접근 범위) 공유 작업공간의 사용자가 허용 상태에서 게시·종료·반려를 기록할 수 있다.
- (범위) 서비스는 외부 플랫폼 API를 부르지 않는다. 게시·종료·반려는 모두 사장님이 누른 기록으로만 바뀐다 (H1).

### 현재 동작과 미확정

- MVP는 수동 게시·종료·반려 기록으로 정리했다. 플랫폼 자동 연동은 제외다 (H1).
- 플랫폼 반려가 실제로 생기는지 (H14)
- 현재 기간이 지나도 자동 종료하지 않는다. 사용자가 종료를 기록한다.
- 일시정지(집행중 ↔ 일시정지)와 예산 소진 자동 제어는 MVP 제외다 (R7).
