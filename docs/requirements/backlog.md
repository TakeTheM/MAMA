## US-01 캡션·해시태그 초안 받기

**셀러 대표로서, 상품·목표·채널·예산을 입력하면 캡션·해시태그 초안을 받고 싶다. 캡션을 처음부터 쓰는 시간을 줄이기 위해서다.**

- 우선순위: 필수
- 관련 기능: F-01
- 경로: 정상
- 관련 상태 전이: 기획중 → 초안 생성됨
- LLM 관여: 예
- 관련 이슈: (다음 주에 채움)

### 인수 조건

- (정상) 기획중 캠페인에 상품명·상품 특징·가격·광고 목표·채널(1개 이상)·예산(금액, 기간)을 모두 입력하고 '초안 만들기'를 누르면, 고른 채널마다 캡션 1개와 해시태그 목록 1개가 만들어지고 상태가 기획중 → 초안 생성됨으로 바뀐다. 상태 기록이 1줄 남는다.
- (정상, 피드백 루프) 같은 셀러에게 성과 평가 완료 캠페인이 있으면, 가장 최근 캠페인의 캡션·해시태그와 성과 숫자·요약(US-05)을 LLM 입력에 함께 넣고, 초안 화면에 참고한 캠페인을 표시한다. 없으면 참고 없이 만들고 아무것도 표시하지 않는다.
- (실패) 필수 입력이 하나라도 비어 있거나 예산 금액·기간이 0 이하이면 LLM을 부르지 않고 빈 항목을 표시한다. 상태는 기획중 그대로다.
- (실패) LLM 호출이 실패하거나, 응답에 고른 채널 중 하나라도 캡션이 없으면 오류를 보여 주고 상태는 기획중 그대로다. 입력한 내용은 지워지지 않는다.
- (권한) 소유 셀러만 초안을 만들 수 있다. 다른 계정의 요청은 거절하고 상태는 바뀌지 않는다.
- (LLM 경계) 초안 생성됨이 되어도 검수 요청은 자동으로 되지 않는다. 다음 상태로는 사장님이 US-02에서 직접 요청해야만 간다.
- (LLM에 보내지 않을 정보) LLM 요청 본문에는 고객 이름·연락처·주소와 매입 단가(원가)가 들어가지 않는다. 피드백 루프 입력도 지난 광고의 문구와 성과 숫자로만 한정한다 (H9).

### 미확정

- 지원 채널이 인스타그램·X·틱톡이 맞는지, 채널별 캡션 글자 수·해시태그 개수 제한 (H2)
- 피드백 루프에 넣을 지난 캠페인 개수와 '성과'의 기준 (H3, H9)
- 초안 다시 만들기 횟수 제한 (LLM 비용, 미팅 1 피드백 2)
- 초안 생성됨 → 기획중 되돌림('다시 기획', 03 3-2)을 허용할지

## US-02 초안 검수 요청하기

**셀러 대표로서, 초안을 고친 뒤 검수를 요청하고 싶다. 광고를 올리기 전에 확인받기 위해서다.**

- 우선순위: 필수
- 관련 기능: F-03
- 경로: 정상
- 관련 상태 전이: 초안 생성됨 → 검수 대기
- LLM 관여: 아니오
- 관련 이슈: (다음 주에 채움)

### 인수 조건

- (정상) 초안 생성됨 캠페인에서 사장님이 캡션·해시태그를 고치고 '검수 요청'을 누르면 고친 내용이 저장되고 상태가 초안 생성됨 → 검수 대기로 바뀐다. 상태 기록이 1줄 남는다.
- (정상) 검수 대기가 되면 그 시점에 저장된 문구로 US-03의 검수가 시작된다. 고치지 않고 바로 요청해도 같다.
- (실패) 고른 채널 중 캡션이 비어 있는 채널이 하나라도 있으면 검수 요청을 거절하고 상태는 초안 생성됨 그대로다.
- (실패) 초안 생성됨이 아닌 상태(기획중, 승인됨, 취소 등)에서 검수 요청을 하면 거절하고 상태는 바뀌지 않는다. 수정 요청 상태에서 다시 요청하는 것은 US-03에서 다룬다.
- (권한) 소유 셀러만 문구를 고치고 검수를 요청할 수 있다. 다른 계정의 요청은 거절한다.

### 미확정

- 검수 대기 중에 문구를 고칠 수 있는지. 고칠 수 있다면 검수를 처음부터 다시 하는지
- 초안을 쓰는 사람과 검수를 요청하는 사람이 다를 수 있는지 (H6)

## US-03 위험 표현 확인하고 수정하기

**셀러 대표로서, 초안에 금지·논란 위험 표현이 있으면 이유와 근거 자료, 고쳐 쓴 문장을 보고 싶다. 무엇이 왜 문제인지 알고 수정하기 위해서다.**

- 우선순위: 필수
- 관련 기능: F-02, F-03
- 경로: 취소·반려
- 관련 상태 전이: 검수 대기 → 수정 요청 (이후 수정 요청 → 검수 대기), 검수 대기 → 승인됨 (위험 표현 없음 + 사장님 승인)
- LLM 관여: 예
- 관련 이슈: (다음 주에 채움)

### 인수 조건

- (반려) 검수 대기 문구에서 협찬 미표시(R1), 거짓·과장(R3), 식품·화장품 효능 표방(R4), 비하·혐오(R5) 위험 표현이 1개 이상 나오면, 표현마다 ① 문구 안의 위치 ② 해당 규칙 번호와 이유 ③ 근거 자료 링크 ④ 고쳐 쓴 문장을 보여 주고 상태가 검수 대기 → 수정 요청으로 바뀐다.
- (반려, 규칙으로 한 번 더 거르기) LLM이 위험 표현을 0개로 답해도, 금지어 규칙 목록에 있는 표현이 문구에 들어 있으면 그 표현을 위험 표현으로 표시하고 수정 요청으로 바꾼다.
- (재검수) 수정 요청 상태에서 사장님이 문구를 고치고 '다시 검수 요청'을 누르면 상태가 수정 요청 → 검수 대기로 바뀌고, 고친 문구로 검수를 다시 한다.
- (승인) 위험 표현이 0개이면 '승인' 버튼이 켜지고, 사장님이 누르면 상태가 검수 대기 → 승인됨으로 바뀐다. 상태 기록에 승인한 계정과 시각이 남는다.
- (거절) 수정 요청 상태에서는 승인 요청을 거절하고 상태는 바뀌지 않는다.
- (실패) LLM 호출이 실패하면 오류를 보여 주고 상태는 검수 대기 그대로다. 승인 버튼은 꺼진 채로 있다.
- (근거 자료) 근거 자료는 팀이 미리 확인해 둔 자료 목록(법령·심사지침 원문, 확인한 기사) 안에서만 보여 준다. LLM이 목록에 없는 링크를 내면 그 링크는 보여 주지 않는다.
- (LLM 경계) 고쳐 쓴 문장은 사장님이 '적용'을 눌러야 문구에 들어간다. LLM 결과만으로는 승인됨이 되지 않는다.
- (권한) 소유 셀러만 고쳐 쓴 문장을 적용하고, 다시 검수를 요청하고, 승인할 수 있다.
- (LLM에 보내지 않을 정보) LLM에는 광고 문구와 상품 카테고리만 보낸다. 고객 정보와 원가는 보내지 않는다.

### 미확정

- 위험 표현이 나오면 수정 요청으로 막을지, 경고만 하고 사장님이 판단할지 (H5, 미팅 1 피드백 1 "수정 여부는 사용자가 선택"과 부딪힘)
- 사장님이 위험 표현을 '문제 없음'으로 넘기고 승인할 수 있는지
- 비하·혐오 검수(R5)를 넣을지 (H12), 식품·화장품 개별 효능 표현 기준 (H7, R4)
- 승인 뒤 문구를 고치면 다시 승인받아야 하는지 (H13)
- 근거 자료 목록의 수집 범위 (H10, RAG)

## US-04 게시 시각·예산 정하기

**셀러 대표로서, 승인된 광고의 게시 예정 시각과 예산을 정하고 싶다. 심사 시간 여유가 부족하면 미리 알림을 받기 위해서다.**

- 우선순위: 필수
- 관련 기능: F-04
- 경로: 정상
- 관련 상태 전이: 승인됨 → 게시 예약됨
- LLM 관여: 아니오
- 관련 이슈: (다음 주에 채움)

### 인수 조건

- (정상) 승인됨 캠페인에서 게시 예정 시각과 예산(금액, 기간)을 입력하고 저장하면 상태가 승인됨 → 게시 예약됨으로 바뀐다. 예산 칸에는 US-01에서 입력한 예산이 기본값으로 들어가 있다.
- (알림) 게시 예정 시각이 저장 시각부터 24시간 안이면 "플랫폼 심사에 24시간 여유가 없습니다" 알림을 보여 준다. 저장은 막지 않는다 (3-3).
- (실패) 게시 예정 시각이 저장 시각보다 과거이거나, 예산 금액·기간이 0 이하이면 거절하고 상태는 승인됨 그대로다.
- (실패) 승인됨이 아닌 상태에서 저장하면 거절하고 상태는 바뀌지 않는다.
- (권한) 소유 셀러만 게시 시각과 예산을 정할 수 있다.
- (범위) 게시 예약됨이 되어도 서비스는 외부 플랫폼에 게시하거나 광고비를 집행하지 않는다. 외부 플랫폼 API를 부르지 않는다 (R6, H1).

### 미확정

- 채널마다 게시 예정 시각을 따로 정하는지
- 게시 예약을 취소하면 승인됨으로 돌아가는지 (03 3-2 '예약 취소'), 캠페인 취소(US-06)와 어떻게 다른지
- TikTok·X 심사 시간과 주말 심사 지연 (S1 자료 조사)

## US-05 성과 요약과 다음 광고 제안 받기

**셀러 대표로서, 광고가 끝난 뒤 성과 숫자를 입력하면 쉬운 말로 된 결과 요약과 다음 광고 제안을 받고 싶다. 이 광고로 수익이 났는지 확인하고 다음 광고에 반영하기 위해서다.**

- 우선순위: 필수
- 관련 기능: F-05
- 경로: 정상
- 관련 상태 전이: 종료 → 성과 평가 완료
- LLM 관여: 예
- 관련 이슈: (다음 주에 채움)

### 인수 조건

- (정상) 종료 캠페인에 노출·클릭·전환·광고비·매출을 입력하면 시스템이 ROAS(매출 ÷ 광고비)를 계산하고, LLM이 그 숫자로 결과 요약과 다음 광고 제안을 쓴다. 상태는 아직 종료 그대로다.
- (LLM 경계) 사장님이 요약을 확인하고 '평가 완료'를 누르면 상태가 종료 → 성과 평가 완료로 바뀐다. 누르기 전에는 바뀌지 않는다.
- (숫자는 시스템이) 화면의 숫자(입력값, ROAS)는 시스템이 계산한 값을 그대로 보여 준다. LLM 출력에 있는 숫자로 바꾸지 않는다.
- (실패) 입력 칸이 하나라도 비어 있거나 음수이면 거절하고 LLM을 부르지 않는다. 광고비가 0이면 ROAS는 '계산할 수 없음'으로 표시한다.
- (실패) LLM 호출이 실패해도 입력한 숫자와 ROAS는 저장하고 보여 준다. 요약이 없으면 '평가 완료'를 누를 수 없고 상태는 종료 그대로다.
- (실패) 종료가 아닌 상태에서 성과를 입력하면 거절한다.
- (피드백 루프) 성과 평가 완료가 된 캠페인의 문구·숫자·요약은 같은 셀러의 다음 캠페인 초안(US-01) 입력으로 쓰인다.
- (권한) 소유 셀러만 성과를 입력하고 평가를 완료할 수 있다.
- (LLM에 보내지 않을 정보) LLM에는 성과 숫자와 광고 문구만 보낸다. 리뷰 작성자 이름·아이디, 주문 번호, 원가는 보내지 않는다.

### 미확정

- '수익'이 실제 이익(수수료·광고비·배송비·원가를 뺀 값)인지 매출·ROAS인지 (H3, F-07)
- 플랫폼 전환 집계 기간이 지난 뒤에만 입력을 받을지 (03 3-3)
- 성과를 플랫폼에서 받아 올 수 있는지, 수동 입력만 할지 (H8)
- 성과 평가 완료 뒤에 숫자를 고칠 수 있는지 (03 3-2는 되돌릴 수 없음)

## US-06 광고 취소하기

**셀러 대표로서, 광고를 올리기 전에 마음이 바뀌면 캠페인을 취소하고 싶다. 필요 없는 광고에 시간과 비용을 쓰지 않기 위해서다.**

- 우선순위: 필수
- 관련 기능: F-03
- 경로: 취소·반려
- 관련 상태 전이: 게시 예약됨 → 취소 (기획중·초안 생성됨 → 취소 포함)
- LLM 관여: 아니오
- 관련 이슈: (다음 주에 채움)

### 인수 조건

- (정상) 기획중·초안 생성됨·게시 예약됨 캠페인에서 사장님이 '캠페인 취소'를 누르면 상태가 취소로 바뀐다. 상태 기록에 이전 상태가 남는다.
- (거절) 집행중·종료·성과 평가 완료 캠페인의 취소 요청은 거절하고 상태는 바뀌지 않는다. "이미 올린 광고는 플랫폼에서 직접 중지해 주세요"를 보여 준다.
- (되돌릴 수 없음) 취소 상태에서는 문구 수정, 검수 요청, 게시 기록 등 상태를 바꾸는 요청을 모두 거절한다.
- (LLM 경계) 취소 전에 보낸 LLM 요청(초안 생성 등)의 결과가 취소 뒤에 도착해도 상태와 문구를 바꾸지 않는다.
- (권한) 소유 셀러만 취소할 수 있다.

### 미확정

- 검수 대기·수정 요청·승인됨에서도 취소할 수 있는지 (03 3-2 표는 "기획중~게시 예약됨", 상태도와 F-03은 3개 상태만 적음)
- 취소한 캠페인을 목록에서 숨길지, 지울 수 있는지
- 취소 사유를 입력받을지

## US-07 게시·종료 기록하기

**셀러 대표로서, 플랫폼에 직접 광고를 올린 뒤 '게시함'과 '종료'를 기록하고 싶다. 광고 한 건의 진행과 결과를 한곳에 남기기 위해서다.**

- 우선순위: 필수
- 관련 기능: F-04
- 경로: 정상, 취소·반려 (플랫폼 반려)
- 관련 상태 전이: 게시 예약됨 → 집행중 → 종료, 게시 예약됨 → 플랫폼 반려 → 수정 요청
- LLM 관여: 아니오
- 관련 이슈: (다음 주에 채움)

### 인수 조건

- (정상) 게시 예약됨 캠페인에서 '게시함'을 누르면 상태가 집행중으로 바뀌고 게시 시각이 기록된다.
- (정상) 집행중 캠페인에서 '종료'를 누르면 상태가 종료로 바뀌고 종료 시각이 기록된다.
- (반려) 게시 예약됨 캠페인에서 '플랫폼 반려'를 고르고 반려 사유를 입력하면 상태가 플랫폼 반려로 바뀐다. 사장님이 '다시 고치기'를 누르면 수정 요청으로 바뀌고, 수정 화면에 반려 사유가 함께 보인다.
- (실패) 반려 사유가 비어 있으면 거절하고 상태는 게시 예약됨 그대로다.
- (실패) 순서를 건너뛰는 요청(게시 예약됨에서 바로 종료, 승인됨에서 게시함 등)은 거절하고 상태는 바뀌지 않는다.
- (실패) 종료 시각이 게시 시각보다 앞서면 거절한다.
- (권한) 소유 셀러만 게시·종료·반려를 기록할 수 있다.
- (범위) 서비스는 외부 플랫폼 API를 부르지 않는다. 게시·종료·반려는 모두 사장님이 누른 기록으로만 바뀐다 (H1).

### 미확정

- 게시·집행을 플랫폼과 자동으로 연동할지 (H1). 연동하면 이 스토리의 전이 주체가 시스템으로 바뀐다
- 플랫폼 반려가 실제로 생기는지 (H14)
- 집행 기간(예: 7일)이 지나면 자동으로 종료할지, 사장님이 누를 때까지 기다릴지
- 일시정지(집행중 ↔ 일시정지)를 MVP에 넣을지 (R7, 5-1에서 자동 일시정지는 제외)
