# F-03 검수·승인·취소

임시 `기획중 → 승인됨` 승인은 제거했습니다. 실제 경로는 `기획중 → 초안 생성됨 → 검수 대기 → 승인됨`이며, 검수 결과가 현재 revision과 일치하고 검수 상태가 completed일 때만 승인할 수 있습니다. 경고가 있어도 사용자 승인으로 진행합니다.

- `POST /{id}/request-review`: US-02 검수 요청·US-03 재검수입니다. 실패 시 검수 대기를 유지하고 재시도합니다.
- `POST /{id}/approve`: 검수 성공 후 사용자가 승인합니다. 자동 승인은 없습니다.
- `POST /{id}/request-revision`: 검수 후 사용자가 수정을 선택하거나 플랫폼 반려 후 다시 고칩니다. 플랫폼 반려 경로는 예약을 비우고 이전 예약·사유는 이력에 보존합니다.
- `PATCH /{id}`: 기획중·초안 생성됨·수정 요청에서만 수정합니다. `content` 문자열 수정은 선택 채널의 캡션에 모두 반영하며, 채널별 수정은 `drafts`를 사용합니다. 두 필드를 동시에 보내면 거절합니다. 수정 후 이전 검수는 stale입니다.
- `POST /{id}/cancel`: 게시 전 캠페인을 취소합니다. 취소는 끝 상태로 모든 변경을 거절합니다. 게시 후에는 플랫폼에서 직접 중지하도록 안내합니다.

취소 허용 상태에 대한 기존 문서의 미정 부분은 ‘게시 전 모든 상태 허용’으로 정했습니다. 취소 중 도착한 LLM 결과와 수정 후 오래된 결과는 상태·revision을 비교해 저장하지 않습니다. `allowed_actions`, `can_approve`는 서버에서 계산합니다.
