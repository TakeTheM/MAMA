- 제품 방향: [중간 미팅 보고서 반영 기록](../../docs/interview/mid-meeting-report.md)

## 현재 기술과 작업공간

- FastAPI·Python 3.13, SQLAlchemy 2.x 동기 Session, Alembic을 사용한다.
- DB 연결은 `DATABASE_URL` 하나로 전달한다. PostgreSQL/Supabase는 psycopg·NullPool·prepared statement 비활성화를 적용한다. MySQL 8.4·PyMySQL과 Compose는 기존 환경 호환 경로다.
- 로그인 없는 공유 작업공간이다. `/api/v1/auth`와 JWT 발급·소유권 검사는 현재 제공하지 않는다. 기존 계정 테이블과 외래키는 과거 데이터 보존을 위해 남아 있다.
- 배포 절차는 `backend`를 Root Directory로 둔 Vercel 기준이다. 프로덕션 빌드에서 마이그레이션하며 프리뷰 DB는 별도로 준비한다.

## 현재 기능과 상태

- F-01: 상품·목표·채널·예산으로 채널별 초안을 만들고 공유 작업공간의 최근 평가 완료 광고를 참고한다. 초안 생성 후 검수 요청은 사용자가 한다.
- F-02·F-03: 검수·재검수·사용자 승인·취소를 제공한다. 위험 표현은 경고이며 검수 완료 상태면 경고가 있어도 승인할 수 있다. 검수 실패·처리 중에는 승인할 수 없다.
- F-04: 일정·예산·게시·종료·플랫폼 반려·다시 고치기·이력을 제공한다. 외부 플랫폼을 호출하거나 예약 시각에 자동 게시하지 않는다.
- F-05: 성과 수동 입력·서버 ROAS 계산·LLM 요약·사용자 평가 완료를 제공한다. 요약 실패 시에도 입력과 ROAS를 보존한다.
- 허용 동작과 시간·상태 검증은 FastAPI가 판단하고 `allowed_actions`로 전달한다. 상태 전이와 이력은 같은 트랜잭션으로 저장하고 행 잠금으로 동시 변경을 직렬화한다.
- LLM 호출 중에는 DB 잠금을 유지하지 않는다. 응답 저장 직전 상태·revision을 다시 확인해 늦은 결과를 거절한다.

## 제품 문서와 검증 범위

필수 스토리와 인수 조건은 [백로그](../../docs/requirements/backlog.md)를 따른다. 계정별 저장·소유권 검사는 보고서의 후속 요구로 남기며 현재 구현 완료로 표시하지 않는다. 실제 AI·DB·배포 전체 흐름과 실패·재시도 검증은 별도이며 코드가 있다는 사실과 시연 검증 완료를 구분한다.
