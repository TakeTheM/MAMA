# F-02 위험 표현 검수

- `POST /api/v1/campaigns/{id}/request-review`: 초안 생성됨·수정 요청에서 검수합니다. 본문을 생략하면 저장된 초안을 사용하고, `{"drafts": {...}}`를 보내면 고친 문구를 먼저 저장합니다. 검수 실패 상태에서는 같은 API로 재시도합니다.
- `GET /api/v1/campaigns/{id}/review`: 검수 진행·완료·실패·오래된 결과와 표현별 위치·규칙·이유·근거 링크·수정안을 조회합니다.
- `POST /api/v1/campaigns/{id}/apply-suggestion`: `{"finding_index": 0}`으로 한 수정안을 명시적으로 적용합니다. 적용 후 결과를 stale로 표시하므로 다른 수정안을 적용하거나 승인하기 전에 다시 검수해야 합니다.
- `GET /api/v1/campaigns/review-sources`: 팀 자료 카드에서 가져온 근거 링크 허용 목록과 로컬 위험 표현 목록을 확인합니다.

**2026-11-03 사용자 결정:** 위험 표현이 나와도 경고만 표시하고 사용자가 승인할 수 있습니다. 백로그의 자동 수정 요청·승인 차단 문장보다 이 결정을 우선합니다. 검수가 실패하거나 현재 문구와 맞지 않는 결과로는 승인할 수 없습니다. 수정을 선택하면 사용자의 동작으로 수정 요청 상태에 들어갑니다.

LLM은 문구·카테고리·공개 근거 목록만 받습니다. 목록 밖의 링크는 제거하고 원문 위치가 틀린 결과는 실패 처리합니다. LLM이 위험을 찾지 못해도 로컬 규칙을 추가 검사합니다. 로컬 규칙은 팀의 초기 경고용 휴리스틱이며 전체 법적 검수를 대신하지 않습니다. 표현 위치는 해당 채널의 `caption` 또는 공백으로 연결한 `hashtags` 안의 Python 문자 인덱스(start 포함, end 제외)입니다.
